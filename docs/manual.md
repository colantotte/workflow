# ワークフローシステム 操作マニュアル

---

## 1. はじめに

### 1.1 システム概要

本システムは、Lark（飛書）と連携した承認ワークフローシステムです。申請の作成から承認・決裁までの一連のプロセスを電子化し、組織内の意思決定を効率化します。

主な特徴:
- Lark アカウントによるシングルサインオン
- 柔軟な承認経路の設定（役職・ロール・特定ユーザー指定）
- 差戻し・引き上げ・条件付き承認などの高度な承認機能
- 動的フォームによる申請書カスタマイズ
- PDF出力機能
- Lark Bot による承認通知

### 1.2 動作環境

| 項目 | 要件 |
|------|------|
| ブラウザ | Google Chrome（最新版推奨）、Microsoft Edge、Safari |
| Lark 環境 | Lark デスクトップアプリ内ブラウザ、Lark モバイルアプリ内ブラウザ |
| ネットワーク | インターネット接続が必要 |

### 1.3 アクセス方法

- **Lark 環境**: Lark アプリ内から本システムのリンクを開くと、自動的に OAuth 認証が行われます。
- **ブラウザ直接アクセス**: `http://localhost:3001` にアクセスし、ユーザーを選択してください。

---

## 2. ログイン・ユーザー選択

### 2.1 Lark 環境での自動認証

Lark アプリ内から本システムを開くと、以下の流れで自動認証が行われます。

1. システムが Lark 環境を検出
2. OAuth 認証フローが自動開始（「認証中...」と表示）
3. Lark の認証画面でアクセスを許可
4. 認証完了後、自動的にログインされ、ヘッダーに氏名とロールバッジが表示

認証情報はブラウザのローカルストレージに保存され、次回アクセス時は再認証不要です。

### 2.2 ブラウザでのユーザー選択（開発・テスト用）

Lark 環境外でアクセスした場合は、ヘッダー右上にユーザー選択プルダウンが表示されます。

1. プルダウンから使用するユーザーを選択
2. 選択したユーザーとしてシステムを操作可能

### 2.3 ログアウト

URL に `?logout=1` パラメータを付与してアクセスすると、保存された認証情報がクリアされます。

---

## 3. ユーザーロールと権限

本システムでは、ユーザーに割り当てられたロールに応じて利用可能な機能が制限されます。

| ロール | 表示名 | 利用可能なタブ | 説明 |
|--------|--------|--------------|------|
| `admin` | 管理者 | 申請一覧、承認待ち、ワークフロー、経路マスタ、承認ロール、インポート | 全機能にアクセス可能 |
| `manager` | マネージャー | 申請一覧、承認待ち、ワークフロー、経路マスタ、承認ロール、インポート | 管理系機能を含む全機能にアクセス可能 |
| `user` | 一般 | 申請一覧、承認待ち | 申請の作成・提出と、承認操作のみ |

ログイン後、ヘッダーの氏名の右側にロールバッジ（管理者 / マネージャー / 一般）が表示されます。

## 4. 申請一覧タブ

### 4.1 概要

「申請一覧」タブでは、自分が作成した申請の一覧確認と新規申請の作成を行います。

### 4.2 一覧表示

画面にはカード形式で申請が表示されます。各カードには以下の情報が含まれます:
- **件名**: 申請のタイトル
- **作成日**: 申請を作成した日時
- **ステータスバッジ**: 現在の申請状態
- **現在のステップ番号**
- **操作ボタン**: 「詳細」ボタン（下書き状態の場合は「提出」ボタンも表示）

### 4.3 ステータスフィルタ

一覧上部のプルダウンで、表示する申請のステータスを絞り込めます。

| ステータス | 表示名 | 説明 |
|-----------|--------|------|
| （空） | すべてのステータス | フィルタなし（全件表示） |
| `draft` | 下書き | 作成済みだが未提出の申請 |
| `pending` | 承認待ち | 提出済みで承認プロセス中の申請 |
| `approved` | 承認完了 | 全ステップの承認が完了した申請 |
| `rejected` | 却下 | 承認者により却下された申請 |
| `remanded` | 差戻し | 承認者により差し戻された申請 |
| `withdrawn` | 取り下げ | 申請者自身が取り下げた申請 |
| `conditional_approve_wait` | コメント待ち | 条件付き承認後、コメント応答を待っている申請 |

### 4.4 新規申請の作成

1. **「+ 新規申請」ボタン**をクリック
2. 新規申請モーダルが表示される

#### 4.4.1 ワークフロー選択

- プルダウンから申請に使用するワークフローを選択
- 有効（アクティブ）なワークフローのみ表示される
- ワークフロー選択後、以下が動的に表示される:
  - **動的フォーム**: ワークフローに設定されたフォームフィールド
  - **承認ルートプレビュー**: 承認ステップの一覧

#### 4.4.2 件名の入力

- 件名は必須項目（最大200文字）
- ワークフローの設定により、件名が自動生成される場合があります:
  - **手動入力**: 自由に入力
  - **基本項目から自動生成**: ワークフロー名 + 日付
  - **フィールドから自動生成**: 入力したフォーム値から自動生成
  - **テンプレート**: 設定されたテンプレートに基づいて自動生成
- 自動生成モードの場合、件名フィールドは読み取り専用（グレー背景）になります

#### 4.4.3 動的フォーム入力

ワークフローに設定されたフォームに従い、必要な情報を入力します。

対応しているフィールドタイプ:

| タイプ | 説明 |
|--------|------|
| テキスト | 一行テキスト入力 |
| 数値 | 数値入力 |
| 日付 | カレンダーから日付選択 |
| 時刻 | 時刻選択（間隔設定あり） |
| 選択肢 | プルダウンから1つ選択 |
| ラジオボタン | ラジオボタンから1つ選択 |
| 複数行テキスト | 複数行テキスト入力 |
| チェックボックス | ON/OFF切替 |
| 社員選択 | 登録ユーザーから選択 |
| 部署選択 | 部署から選択 |
| 自動計算 | 他フィールドの値から自動計算（編集不可） |
| 明細テーブル | 行追加可能な表形式入力 |

**フォームの高度な機能:**
- **必須マーク**: 必須フィールドには赤い「*」が表示されます
- **ツールチップ**: 「?」アイコンにマウスを合わせると補足説明が表示されます
- **表示条件**: 別のフィールドの値に応じて表示/非表示が切り替わるフィールドがあります
- **大小比較バリデーション**: フィールド間の値の大小関係が正しくない場合、エラーメッセージが表示されます
- **自動計算**: 数式が設定されたフィールドは、関連フィールドの入力に応じて自動的に値が計算されます

#### 4.4.4 明細テーブル

明細テーブルが含まれるフォームでは:
1. 「+ 行追加」ボタンで行を追加
2. 各行の各列に値を入力
3. 行の「x」ボタンで行を削除
4. 合計行が設定されている列は、自動的に合計値が表示される

#### 4.4.5 承認ルートプレビュー

ワークフロー選択後、画面下部に承認ルートのプレビューが表示されます。各ステップのステップ番号、ラベル、承認タイプ（役職による承認/承認ロールによる承認/特定ユーザーによる承認）を確認できます。

#### 4.4.6 下書き保存 / 提出

- **下書き保存**: 「下書き保存」ボタンをクリック。申請が `draft` 状態で保存されます。後から編集・提出が可能です。
- **提出**: 「提出」ボタンをクリック。申請が `pending` 状態になり、承認プロセスが開始されます。最初の承認者に Lark 通知が送信されます。

### 4.5 下書きの提出

申請一覧で下書き状態の申請には「提出」ボタンが表示されます。クリックすると承認プロセスが開始されます。

### 4.6 申請詳細の確認

一覧で「詳細」ボタンをクリックすると、申請詳細モーダルが表示されます。

#### 表示される情報:

**基本情報セクション:**
- 文書番号（自動採番されている場合）
- ステータス
- 作成日
- 提出日
- 取下日（取り下げ済みの場合）

**承認ルートセクション:**
- 各ステップのステップ番号、ラベル、役割タイプ（承認者/決裁者/業務担当者/通知）
- 承認者の氏名と承認状態（承認済み ✓ / 却下 ✗）
- スキップされたステップにはスキップ理由が表示（空席/同一人物/条件不該当）
- 印影（承認済みステップに表示）
- 期限情報（設定されている場合）と残日数

**承認履歴セクション:**
- タイムライン形式で承認・却下・差戻し等のアクションを時系列表示
- 各アクションのアイコン、実行者名、日時、コメント

**操作ボタン:**
申請のステータスと閲覧者の権限に応じて、以下のボタンが表示されます:
- 承認 / 却下 / 差戻し（現在のステップの承認者の場合）
- 条件付承認（決裁者ステップの承認者の場合）
- 経路変更（ワークフローで経路変更が許可されている場合）
- 引き上げ（後続ステップの承認者で、引き上げが許可されている場合）
- 取り下げ（申請者自身で、取り下げが許可されている場合）
- 再利用（完了/却下/取り下げ済みの申請で、再利用が許可されている場合）
- PDF出力

## 5. 承認待ちタブ

### 5.1 概要

「承認待ち」タブでは、自分が承認者として割り当てられている申請の一覧が表示されます。

### 5.2 承認待ち一覧

各カードに以下の情報が表示されます:
- 申請の件名
- 申請者名
- 提出日
- 現在のステップ番号
- 操作ボタン（詳細、承認、却下、差戻し）

### 5.3 承認アクション

#### 5.3.1 承認

1. 「承認」ボタンをクリック
2. 承認アクションモーダルが表示される
3. コメントを入力（任意）
4. 「承認」ボタンをクリックして実行

承認後の動作:
- 次の承認ステップに進む（次の承認者に Lark 通知が送信される）
- 全ステップ完了の場合、申請が「承認完了」となり申請者に通知される
- スキップ条件に該当する後続ステップは自動的にスキップされる

#### 5.3.2 却下

1. 「却下」ボタンをクリック
2. 却下アクションモーダルが表示される
3. コメントを入力（**必須**）
4. 「却下」ボタンをクリックして実行

却下後、申請は「却下」ステータスとなり、承認プロセスが終了します。申請者に Lark 通知が送信されます。

#### 5.3.3 差戻し

差戻しには3つのモードがあります。

1. 承認待ち一覧または詳細画面で「差戻し」ボタンをクリック
2. 差戻し設定モーダルが表示される
3. 差戻しモードを選択:

| モード | 説明 |
|--------|------|
| **申請者に戻す（経路最初から再承認）** | 申請を下書き状態に戻す。申請者が再提出すると、承認経路の最初のステップから再度承認が必要。 |
| **差戻先を指定する** | 特定のステップを指定して差し戻す。指定したステップから承認プロセスを再開。 |
| **直前のステップに戻す（再承認不要）** | 直前のステップに戻す。差戻先のステップから承認を再開。 |

4. 「差戻先を指定する」を選んだ場合は、差戻先ステップをプルダウンから選択
5. コメントを入力（**必須**）
6. 「差戻し」ボタンをクリックして実行

#### 5.3.4 条件付き承認

決裁者（final_approver）ステップの承認者のみが使用できる特殊な承認方法です。

1. 詳細画面で「条件付承認」ボタンをクリック
2. 条件付き承認モーダルが表示される
3. 通過済みの承認ステップの中から、コメントを要求するステップを選択（チェックボックス）
4. コメントを入力（任意）
5. 「条件付き承認」ボタンをクリックして実行

実行後:
- 申請のステータスが「コメント待ち」に変更される
- 指定されたステップの承認者がコメントを返答するまで、他の承認者はアクション不可
- 全てのコメントが揃うと、ステータスが「承認待ち」に戻る

#### 5.3.5 引き上げ承認

後続ステップの承認者が、中間の承認ステップをスキップして直接承認する機能です。ワークフローで引き上げが許可されている場合のみ使用可能です。

1. 詳細画面で「引き上げ」ボタンをクリック
2. 確認モーダルが表示される（「中間の承認ステップは自動的に承認扱いとなります」という説明）
3. 「引き上げ承認」ボタンをクリックして実行

実行後:
- 現在のステップから引き上げ実行者のステップまでの中間ステップが自動承認扱い
- 引き上げ実行者のステップが承認される
- 後続のステップがあればそこに進む、なければ承認完了

#### 5.3.6 取り下げ（申請者のみ）

承認待ち状態の申請を、申請者自身が取り下げる機能です。ワークフローで取り下げが許可されている場合のみ使用可能です。

1. 詳細画面で「取り下げ」ボタンをクリック（申請者本人のみ表示）
2. 確認モーダルが表示される（「取り下げ後は承認プロセスが停止します」という説明）
3. 「取り下げ」ボタンをクリックして実行

#### 5.3.7 経路変更

承認経路を動的に変更する機能です。ワークフローで経路変更が許可されている場合のみ使用可能です。

1. 詳細画面で「経路変更」ボタンをクリック
2. 経路変更モーダルが表示される
3. 追加する承認者をプルダウンから選択
4. ラベルを入力（例: 「追加承認」）
5. コメントを入力（任意）
6. 「経路変更」ボタンをクリックして実行

#### 5.3.8 再利用

承認完了・却下・取り下げ済みの申請の内容をコピーして、新しい下書き申請を作成する機能です。ワークフローで再利用が許可されている場合のみ使用可能です。

1. 詳細画面で「再利用」ボタンをクリック
2. 元の申請内容がコピーされ、件名に「[再利用]」が付与された新しい下書きが作成される
3. 申請一覧に遷移し、新しい下書きの詳細画面が表示される

#### 5.3.9 PDF出力

申請内容と承認経路をPDFファイルとして出力する機能です。

1. 詳細画面で「PDF出力」ボタンをクリック
2. ブラウザの新しいタブでPDFがダウンロードまたは表示される

## 6. ワークフロー管理タブ（管理者/マネージャー）

### 6.1 概要

「ワークフロー」タブでは、申請に使用するワークフローの定義を管理します。このタブは管理者およびマネージャーロールのユーザーのみ利用可能です。

### 6.2 ワークフロー一覧

カード形式でワークフローが表示されます。各カードには以下の情報が含まれます:
- ワークフロー名
- 説明
- カテゴリバッジ（一般/経費精算/稟議/休暇申請）
- 有効/無効バッジ

カードをクリックするとワークフロー詳細画面が開きます。

### 6.3 新規ワークフロー作成

1. 「+ 新規ワークフロー」ボタンをクリック
2. 新規ワークフローモーダルが表示される
3. 以下の項目を入力:

| 項目 | 必須 | 説明 |
|------|------|------|
| ワークフロー名 | はい | ワークフローの名称（最大200文字） |
| カテゴリ | いいえ | 一般 / 経費精算 / 稟議 / 休暇申請 から選択 |
| 説明 | いいえ | ワークフローの説明文 |
| 有効 | - | チェックを外すとワークフローが無効化され、新規申請で使用不可に |

4. 「保存」ボタンをクリック

### 6.4 ワークフロー詳細・編集

ワークフロー一覧でカードをクリックすると、詳細モーダルが表示されます。

**表示される情報:**
- 基本情報（カテゴリ、説明、有効/無効）
- 承認ステップ一覧

**操作ボタン（管理者/マネージャーのみ）:**
- **編集**: ワークフローの基本情報を編集
- **コピー**: ワークフローを複製（新しい名前を入力）
- **削除**: ワークフローを削除（確認ダイアログあり）

### 6.5 承認ステップ管理

ワークフロー詳細画面内で承認ステップの追加・削除を行います。

#### 6.5.1 ステップ追加

1. 「+ ステップ追加」ボタンをクリック
2. 承認ステップ追加モーダルが表示される
3. 以下の項目を設定:

| 項目 | 必須 | 説明 |
|------|------|------|
| ステップ順序 | はい | 承認順序を指定する数値（1から開始） |
| 承認タイプ | はい | 以下から選択（後述） |
| ラベル | いいえ | 表示用のステップ名（例: 「課長承認」「部長承認」） |
| 必須ステップ | - | チェック時、このステップは必ず通過が必要 |
| 同一人物の場合スキップ | - | 前のステップと同じ承認者の場合にスキップ |
| 空席の場合スキップ | - | 承認者が未割当の場合にスキップ |

**承認タイプの詳細:**

| 承認タイプ | 設定項目 | 説明 |
|-----------|---------|------|
| 役職指定 | 役職名（例: 課長、部長） | 申請者の所属組織における指定役職のユーザーが承認者になる |
| 承認ロール指定 | 承認ロール名（例: 経理承認者） | 指定した承認ロールを持つユーザーが承認者になる |
| 特定ユーザー指定 | ユーザー選択 | 指定したユーザーが直接承認者になる |

4. 「追加」ボタンをクリック

#### 6.5.2 ステップ削除

各ステップの右側にある「削除」ボタンをクリックすると、確認ダイアログの後にステップが削除されます。

## 7. 経路マスタ管理タブ（管理者/マネージャー）

### 7.1 概要

「経路マスタ」タブでは、承認経路のテンプレートを管理します。経路マスタを使用すると、ワークフローごとに異なる承認経路パターンを定義し、申請時に適切な経路を自動選択させることができます。

このタブは管理者およびマネージャーロールのユーザーのみ利用可能です。

### 7.2 経路マスタ一覧

カード形式で経路マスタが表示されます。上部のプルダウンでワークフローごとにフィルタできます。

各カードに表示される情報:
- 経路名
- 説明
- 有効/無効バッジ
- 経路タイプバッジ（基本/役職別/部署別/個人別）
- 標準経路バッジ（標準経路の場合）

各カードの操作ボタン:
- **編集**: 経路マスタの基本情報を編集
- **コピー**: 経路マスタをステップごとコピー
- **削除**: 経路マスタを削除（確認ダイアログあり、ステップも全て削除）

カードをクリックすると詳細画面が表示されます。

### 7.3 新規経路作成

1. 「+ 新規経路」ボタンをクリック
2. 経路マスタ作成モーダルが表示される
3. 以下の項目を入力:

| 項目 | 必須 | 説明 |
|------|------|------|
| 名称 | はい | 経路マスタの名前 |
| 説明 | いいえ | 経路の説明 |
| ワークフロー | はい | 紐づけるワークフロー（有効なもののみ表示） |
| 経路タイプ | いいえ | 以下から選択 |

| 標準経路 | - | チェック時、このワークフローの標準経路として使用 |

**経路タイプ:**

### 7.4 経路詳細・ステップ管理

**表示される情報:**

**操作ボタン:**
- **CSVエクスポート**: ステップ情報をCSV形式でダウンロード
- **編集**: 経路マスタの基本情報を編集

### 7.5 経路コピー

## 8. 承認ロール管理タブ（管理者/マネージャー）

### 8.1 概要

「承認ロール」タブでは、ワークフロー専用の承認グループ（承認ロール）を管理します。承認ロールは、組織の役職とは別に、ワークフローの承認ステップで使用するための仮想的な役割です。

このタブは管理者およびマネージャーロールのユーザーのみ利用可能です。

**承認ロールの例:**
- 経理承認者: 経費精算の承認を担当するグループ
- 取締役決裁: 取締役会決裁事項の承認グループ
- 人事承認者: 人事関連申請の承認グループ

### 8.2 承認ロール一覧

カード形式で承認ロールが表示されます。各カードには以下の情報が含まれます:
- ロール名
- 説明
- 有効/無効バッジ

カードをクリックすると詳細画面が開きます。

### 8.3 承認ロール作成

1. 「+ 新規承認ロール」ボタンをクリック
2. 承認ロール作成モーダルが表示される
3. 以下の項目を入力:

| 項目 | 必須 | 説明 |
|------|------|------|
| ロール名 | はい | 承認ロールの名称（例: 経理承認者） |
| 説明 | いいえ | ロールの説明文 |
| 有効 | - | チェックを外すとロールが無効化され、承認ステップで使用不可に |

4. 「保存」ボタンをクリック

### 8.4 承認ロール詳細・編集・削除

承認ロール一覧でカードをクリックすると、詳細モーダルが表示されます。

**表示される情報:**
- 基本情報（説明、有効/無効）
- 割り当てメンバー一覧（メンバー数と各メンバーの氏名・メールアドレス）

**操作ボタン:**
- **編集**: ロール名・説明・有効フラグを編集
- **削除**: 承認ロールを削除（確認ダイアログあり）

### 8.5 メンバー管理

承認ロールにユーザーを割り当て（または解除）します。

#### 8.5.1 メンバー追加

1. 承認ロール詳細画面で「+ メンバー追加」ボタンをクリック
2. メンバー追加モーダルが表示される
3. 以下の項目を設定:

| 項目 | 必須 | 説明 |
|------|------|------|
| ユーザー | はい | 割り当てるユーザーを選択（有効なユーザーのみ表示） |
| 対象組織コード | いいえ | 空欄の場合は全組織対象。特定の組織のみに限定する場合に指定 |
| 有効開始日 | いいえ | ロール割り当ての開始日（空欄の場合は即時有効） |
| 有効終了日 | いいえ | ロール割り当ての終了日（空欄の場合は無期限） |

4. 「追加」ボタンをクリック

#### 8.5.2 メンバー解除

1. 承認ロール詳細画面のメンバー一覧で、解除したいメンバーの「解除」ボタンをクリック
2. 確認ダイアログで「OK」をクリック

### 8.6 承認ステップでの使用

ワークフローの承認ステップを追加する際、承認タイプで「承認ロール指定」を選択すると、登録済みの有効な承認ロールがドロップダウンで表示されます。

承認ステップに承認ロールが設定されると、申請時にそのロールに割り当てられたメンバーが自動的に承認者として解決されます。対象組織コードが設定されているメンバーの場合は、申請者の所属組織と一致する場合のみ承認者として割り当てられます。

## 9. 代理設定

### 9.1 概要

代理設定では、承認者が不在の場合に別のユーザーに承認権限を委任できます。

### 9.2 代理タイプ

| タイプ | 説明 |
|--------|------|
| 申請代理 (`application`) | 他のユーザーに代わって申請を作成・提出 |
| 処理代理 (`processing`) | 他のユーザーに代わって承認・却下・差戻しを実行 |

### 9.3 代理設定の項目

| 項目 | 必須 | 説明 |
|------|------|------|
| 委任元ユーザー | はい | 権限を委任するユーザー |
| 代理者ユーザー | はい | 代理操作を行うユーザー |
| 代理タイプ | はい | 申請代理 / 処理代理 |
| 対象役割タイプ | いいえ | 代理対象とする役割（承認者/決裁者/業務担当者/通知）を指定 |
| 有効開始日 | はい | 代理期間の開始日 |
| 有効終了日 | いいえ | 代理期間の終了日（空欄の場合は無期限） |
| 有効 | - | チェックを外すと代理設定が無効化 |

### 9.4 代理処理の自動通知

ワークフローの設定により、代理処理のタイムアウト通知を自動送信できます。

| 設定項目 | 説明 |
|---------|------|
| `proxyProcessingAutoNotify` | タイムアウト時に代理者へ自動通知 |
| `proxyProcessingTimeoutDays` | 通知までの待機日数（1〜30日） |

## 10. データインポートタブ（管理者/マネージャー）

### 10.1 概要

「インポート」タブでは、CSVファイルを使用して組織データやユーザーデータを一括登録できます。また、Larkのメンバー情報を自動同期する機能も提供しています。このタブは管理者およびマネージャーロールのユーザーのみ利用可能です。

### 10.2 組織マスタインポート

組織（部署）データをCSV形式で一括登録します。

1. 「テンプレートDL」ボタンで CSV テンプレートをダウンロード
2. テンプレートに従い組織データを入力
3. 「CSVファイル選択」ボタンでファイルを選択
4. プレビューが表示される（有効件数 / エラー件数）
5. エラーがある場合、行番号・列名・エラー内容が表示される
6. 「インポート実行」ボタンをクリックしてインポート

### 10.3 ユーザーインポート

ユーザーデータをCSV形式で一括登録します。手順は組織マスタインポートと同様です。

1. 「テンプレートDL」ボタンで CSV テンプレートをダウンロード
2. テンプレートに従いユーザーデータを入力
3. 「CSVファイル選択」ボタンでファイルを選択
4. プレビュー確認後、「インポート実行」ボタンでインポート

### 10.4 CSVテンプレートダウンロード

各インポートセクションの「テンプレートDL」リンクをクリックすると、対応するCSVテンプレートがダウンロードされます。テンプレートにはヘッダー行と列の説明が含まれています。

### 10.5 Lark メンバー同期

Lark（飛書）の管理コンソールに登録されているメンバー・部署情報を自動で同期する機能です。

1. インポートタブの「Lark メンバー同期」セクションにある「同期実行」ボタンをクリック
2. 同期中は「同期中...」と表示される
3. 完了後、同期結果（部署数・ユーザー数）が表示される

**同期の動作:**
- Lark Contact API から部署一覧とユーザー一覧を取得
- 新規ユーザーは自動登録、既存ユーザーは情報を更新
- Lark に存在しないユーザーは自動的に無効化（ただし、取得件数が0件の場合は安全のため無効化しない）

## 11. 承認フローの詳細説明

### 11.1 承認ステップの種類と動作

各承認ステップには「役割タイプ」が設定されており、動作が異なります。

| 役割タイプ | 表示名 | 説明 |
|-----------|--------|------|
| `approver` | 承認者 | 通常の承認者。承認・却下・差戻しが可能。 |
| `final_approver` | 決裁者 | 最終決裁権限を持つ承認者。条件付き承認も使用可能。 |
| `handler` | 業務担当者 | 業務処理を行う担当者ステップ。 |
| `notifier` | 通知 | 通知のみのステップ。承認不要で自動通過。 |

### 11.2 複数承認者モード

1つのステップに複数の承認者が設定されている場合の動作モード:

| モード | 説明 |
|--------|------|
| 単独承認 | 最初の1人が承認すれば通過 |
| 全員承認 | 全員が承認しないと通過しない |
| グループ承認 | 指定人数以上が承認すれば通過 |
| 通知のみ | 承認不要、通知のみ |

### 11.3 スキップ条件

以下の条件に該当する場合、承認ステップは自動的にスキップされます:

| スキップ条件 | 表示 | 説明 |
|-------------|------|------|
| 空席スキップ | 「空席のためスキップ」 | 承認者が未割当（対象者不在）の場合 |
| 同一人物スキップ | 「同一人物のためスキップ」 | 前のステップの承認者と同一人物の場合 |
| 条件不該当 | 「条件不該当のためスキップ」 | ステップの適用条件（金額等）に該当しない場合 |

### 11.4 差戻し3モード

差戻しには以下の3つのモードがあります。承認者は差戻し時にモードを選択できます。

| モード | 動作 |
|--------|------|
| **申請者に戻す（経路最初から再承認）** | 申請のステータスが「下書き」に戻る。申請者が再提出すると、承認経路の最初（ステップ1）から再承認が必要。 |
| **差戻先を指定する** | 指定したステップに直接差し戻す。そのステップから承認プロセスを再開。差戻先以前の通過済みステップの承認は維持。 |
| **直前のステップに戻す（再承認不要）** | 直前のステップに戻す。直前の承認者が再度承認すればプロセスが再開。 |

### 11.5 引き上げ承認の仕組み

引き上げ承認は、後続ステップの承認者が現在の承認ステップをスキップして直接承認する機能です。

**前提条件:**
- ワークフローで `allowPullUp`（引き上げ許可）が有効であること
- 操作者が、現在のステップより後のステップに承認者として割り当てられていること

**動作:**
1. 現在のステップから引き上げ実行者のステップまでの全中間ステップが「引き上げ承認」として自動記録
2. 引き上げ実行者のステップが「承認」として記録
3. その後のステップがあれば次に進む、なければ承認完了

### 11.6 条件付き承認の仕組み

決裁者ステップの承認者が、通過済みの承認者にコメントを要求する機能です。

**前提条件:**
- 操作者のステップの役割タイプが `final_approver`（決裁者）であること

**動作:**
1. 決裁者が通過済みステップから対象を選択してコメントを要求
2. 申請のステータスが「コメント待ち」に変更
3. 指定された承認者がコメントを返答
4. 全てのコメントが揃うとステータスが「承認待ち」に戻り、決裁者が改めてアクション可能

### 11.7 経路変更の仕組み

承認プロセス中に、現在のステップの承認者が承認経路を動的に変更する機能です。

**前提条件:**
- ワークフローで `allowRouteChange`（経路変更許可）が有効であること
- 操作者が現在のステップの承認者であること

**動作:**
1. 承認者が追加する承認者（ユーザー）とラベルを指定
2. 現在のステップ以降に新しい承認ステップが追加
3. 経路変更は承認履歴に記録される

### 11.8 期限管理

承認ステップに期限（日数）が設定されている場合:
- 申請詳細画面に残日数が表示される
- 残り1日以下になると赤色（urgent）で強調表示
- 期限切れの場合は「期限切れ」と表示

### 11.9 Lark 通知

以下のタイミングで Lark Bot を通じて自動通知が送信されます:
- 申請提出時: 最初の承認者に通知
- 承認時: 次のステップの承認者に通知
- 承認完了時: 申請者に通知
- 却下時: 申請者に通知（却下コメント付き）
- 差戻し時: 申請者に通知（差戻しコメント付き）

## 12. 職務権限基準表について

本システムでは、組織の職務権限基準表に基づいてワークフローを定義できます。

### 12.1 ワークフローカテゴリ

| カテゴリ | 用途 |
|---------|------|
| 一般 | 汎用的な申請・稟議 |
| 経費精算 | 経費精算関連の申請 |
| 稟議 | 稟議申請 |
| 休暇申請 | 有給休暇・特別休暇等の申請 |

### 12.2 サンプルワークフロー

システムには以下のサンプルワークフローが含まれています:

| ワークフロー名 | カテゴリ | 説明 |
|--------------|---------|------|
| 経費精算（10万円未満） | 経費精算 | 10万円未満の経費精算申請 |
| 経費精算（10万円以上） | 経費精算 | 10万円以上の経費精算申請（取締役決裁必要） |
| 稟議申請 | 稟議 | 一般稟議申請 |
| 休暇申請 | 休暇申請 | 有給休暇・特別休暇申請 |

### 12.3 フォームフィールドの設定

各ワークフローには専用のフォーム（formSchema）を設定できます。例:

**経費精算フォーム:**
- 金額（数値・必須）
- 支出日（日付・必須）
- 経費区分（選択肢: 交通費/交際費/消耗品費/通信費/その他・必須）
- 内容・目的（複数行テキスト・必須）
- 領収書添付（チェックボックス）

**休暇申請フォーム:**
- 休暇種別（選択肢: 有給休暇/特別休暇/代休/欠勤・必須）
- 開始日（日付・必須）
- 終了日（日付・必須）
- 理由（複数行テキスト・任意）

[下書き] ---(提出)---> [承認待ち] ---(承認)---> [承認完了]
   ^                      |

   |                      |

## 付録C: トラブルシューティング

| 症状 | 対処法 |
|------|--------|
| ログインできない | Lark アプリを再起動してから再度アクセスしてください |
| 承認ボタンが表示されない | 現在のステップの承認者として割り当てられているか確認してください |
| ワークフロータブが表示されない | 管理者またはマネージャーロールが必要です。システム管理者にお問い合わせください |
| 申請が提出できない | 必須フィールドが全て入力されているか確認してください |
| 差戻しができない | コメントの入力は必須です |
| 引き上げボタンが表示されない | ワークフローで引き上げが許可されているか、後続ステップの承認者であるか確認してください |
| 取り下げボタンが表示されない | 申請者本人であること、ワークフローで取り下げが許可されていることを確認してください |
| 承認ロールタブが表示されない | 管理者またはマネージャーロールが必要です |
| 承認ロールにメンバーを追加できない | 管理者ロールが必要です。また、対象ユーザーが有効であることを確認してください |
| 承認ロール指定のステップで承認者が解決されない | 承認ロールにメンバーが割り当てられているか確認してください。対象組織コードが設定されている場合、申請者の所属組織と一致する必要があります |
| Lark同期でユーザーが更新されない | Larkアプリの権限スコープ（contact:user.base:readonly）が正しく設定されているか確認してください |
| 通知が届かない | Lark Bot の設定を確認してください |
