## 1. システム概要

### 1.1 本システムについて

本システムは、社内の各種申請・承認業務を電子化するワークフローシステムです。Lark（ラーク）と連携し、組織構造・ユーザー情報を同期しながら、35種類のワークフローに対応した柔軟な承認経路を提供します。

### 1.2 主な機能

| 機能 | 説明 |
|------|------|
| 申請作成・提出 | 各種申請書をフォーム入力で作成・提出 |
| 承認処理 | 承認・却下・差戻し・条件付承認 |
| 経路マスタ | 承認経路テンプレートの管理 |
| 代理設定 | 不在時の代理申請・代理承認 |
| CSV一括管理 | 経路・組織・ユーザーの一括インポート/エクスポート |
| PDF出力 | 申請書のPDF出力 |
| Lark連携 | Lark認証・組織同期 |

### 1.3 ユーザー権限

| 権限 | 申請 | 承認 | ワークフロー管理 | 経路マスタ管理 | インポート |
|------|:----:|:----:|:---------------:|:-------------:|:---------:|
| **一般ユーザー** (user) | O | O※ | - | - | - |
| **マネージャー** (manager) | O | O※ | O | O | O |
| **管理者** (admin) | O | O※ | O | O | O |

※ 承認ステップに割り当てられている場合のみ

## 2. ログインと画面構成

### 2.1 ログイン方法

**Lark環境（アプリ内）の場合:**
1. Larkアプリからワークフローシステムを開く

**開発・テスト環境の場合:**

| **経路マスタ** | 管理者・マネージャー | 承認経路テンプレートの管理 |

## 3. 申請の作成と提出

### 3.1 新規申請の作成

1. 「申請一覧」タブの **「新規申請」** ボタンをクリック
2. **ワークフロー選択**: ドロップダウンから申請種別を選択
3. **件名入力**: 最大200文字（ワークフロー設定により自動入力される場合あり）
4. **フォーム入力**: ワークフローに応じた動的フォームが表示される
5. **承認経路プレビュー**: 提出前に承認ステップを確認可能

### 3.2 フォーム入力フィールド

ワークフローごとに以下のフィールドタイプが使用されます：

| フィールドタイプ | 説明 | 例 |
|----------------|------|------|
| テキスト | 1行テキスト入力 | 目的、件名 |
| 数値 | 数値入力（最小・最大値制限あり） | 金額 |
| 日付 | 日付選択 | 支出日、開始日 |
| セレクト | ドロップダウン選択 | 経費区分、休暇種別 |
| テキストエリア | 複数行テキスト | 詳細内容、理由 |
| チェックボックス | はい/いいえ | 領収書添付 |
| 時刻 | 時刻選択（5〜30分間隔） | 開始時刻 |
| ラジオボタン | 排他選択 | 区分選択 |
| 社員選択 | ユーザー一覧から選択 | 担当者 |
| 部署選択 | 組織一覧から選択 | 対象部署 |
| 自動計算 | 他のフィールドから自動計算 | 合計金額 |
| 明細テーブル | 行追加・削除可能な表 | 経費明細 |

**フォームの高度な機能:**
- **表示条件**: 他のフィールドの値に応じてフィールドの表示/非表示を切り替え
- **必須条件**: 条件に応じて必須/任意を動的に変更
- **大小比較バリデーション**: 開始日 < 終了日などの検証
- **ツールチップ**: フィールドにヘルプテキストを表示

### 3.3 下書き保存と提出

| 操作 | 説明 |
|------|------|
| **下書き保存** | フォーム内容を保存し、後から編集可能。承認フローは開始されない |
| **提出** | 承認フローを開始。ステータスが「承認待ち」に変わる |

### 3.4 申請一覧のフィルタ

以下のステータスでフィルタリング可能：

| ステータス | 説明 |
|-----------|------|
| 下書き | 未提出の申請 |
| 承認待ち | 承認フロー進行中 |
| 承認完了 | 全ステップ承認済み |
| 却下 | いずれかのステップで却下 |
| 差戻し | 差し戻された申請 |
| 取り下げ | 申請者が取り下げた申請 |
| コメント待ち | 条件付承認でコメント待ち |

## 4. 承認・却下・差戻し

### 4.1 承認待ち一覧

「承認待ち」タブには、現在ログインユーザーが承認すべき申請が表示されます。

### 4.2 基本操作

#### 承認
1. 承認待ち一覧から対象の申請をクリック
2. 申請内容を確認
3. コメントを入力（任意）
4. **「承認」** ボタンをクリック
5. 次のステップの承認者に移行（最終ステップの場合は承認完了）

#### 却下
1. 申請詳細を開く
2. コメントを入力（却下理由）
3. **「却下」** ボタンをクリック
4. 申請は「却下」ステータスになる

#### 差戻し
1. 申請詳細を開く
2. **「差戻し」** ボタンをクリック
3. 差戻しモードを選択（下記参照）
4. コメントを入力
5. 実行

### 4.3 差戻しモード

| モード | 動作 | 再承認 |
|--------|------|--------|
| **申請者に戻す** | 申請者に差戻し、ステップ1から再承認 | 全ステップ再承認 |
| **差戻先を指定する** | 指定したステップに差戻し | 指定ステップ以降を再承認 |
| **直前のステップに戻す** | 1つ前のステップに差戻し | 再承認不要でそのステップから再開 |

## 5. 高度な承認操作

### 5.1 条件付承認

**対象**: 決裁者（final_approver）ロールのステップのみ

決裁者が、過去の承認ステップの承認者に対して追加コメントを求める機能です。

1. 決裁者が **「条件付承認」** をクリック
2. コメントを求めるステップを選択
3. 該当ステップの承認者にコメント依頼が送られる
4. コメント提出後、決裁者が最終判断

### 5.2 経路変更

**対象**: ワークフロー設定で `allowRouteChange` が有効な場合

承認途中で承認経路にステップを追加する機能です。

1. 承認者が **「経路変更」** をクリック
2. 追加するステップ情報を入力
3. 現在の経路に新しい承認者が追加される

### 5.3 引き上げ（プルアップ）

**対象**: ワークフロー設定で `allowPullUp` が有効な場合

後のステップの承認者が、途中のステップを飛ばして承認を引き上げる機能です。

例: 部長承認待ちの申請を、本部長が直接承認する

### 5.4 取り下げ

**対象**: 申請者本人、ステータスが「承認待ち」の場合

1. 申請詳細を開く
2. **「取り下げ」** ボタンをクリック
3. 申請は「取り下げ」ステータスになる

### 5.5 再利用

**対象**: 完了・却下・取り下げ済みの申請

過去の申請内容をコピーして新しい下書きを作成します。

1. 対象の申請詳細を開く
2. **「再利用」** ボタンをクリック
3. 内容がコピーされた新しい下書きが作成される

## 6. 経路マスタ管理

> **対象**: 管理者・マネージャーのみ

### 6.1 経路マスタとは

経路マスタは、ワークフローの承認経路テンプレートです。1つのワークフローに対して複数の経路マスタを設定でき、申請者の条件（役職・部署・個人）に応じて最適な経路が自動選択されます。

### 6.2 経路タイプ

| タイプ | 説明 | 優先度 |
|--------|------|--------|
| **基本** (basic) | 全員に適用されるデフォルト経路 | 低（1） |
| **役職別** (by_position) | 特定の役職向けの経路 | 中（2） |
| **部署別** (by_department) | 特定の部署向けの経路 | 高（3） |
| **個人別** (by_individual) | 特定の個人向けの経路 | 最高（4） |

**自動選択ロジック**: 申請者の条件に合致する経路のうち、優先度が最も高い経路が自動適用されます。

### 6.3 経路マスタの作成

1. 「経路マスタ」タブを開く
2. **「経路マスタ作成」** ボタンをクリック
3. 以下を入力：
   - **経路名**: テンプレートの名前
   - **説明**: 経路の目的・用途
   - **ワークフロー**: 紐づけるワークフロー
   - **経路タイプ**: basic / by_position / by_department / by_individual
   - **優先度**: 1〜100（数値が大きいほど高優先）
   - **標準経路フラグ**: ONにすると標準経路として表示
4. 保存後、ステップを追加

### 6.4 ステップの追加

経路マスタにステップ（承認段階）を追加します：

| 設定項目 | 説明 |
|---------|------|
| **ステップ順** | 承認の順番（1, 2, 3...） |
| **ステップ名** | 表示名（例: 「課長承認」「部長決裁」） |
| **ステップタイプ** | position（役職） / role（承認ロール） / specific_user（特定ユーザー） |
| **役割タイプ** | 承認者 / 決裁者 / 業務担当者 / 通知 |
| **承認方法** | 順次 / 全員 / グループ / 通知のみ |
| **必要人数** | グループ承認時の必要承認者数 |
| **必須** | このステップが必須かどうか |
| **期限日数** | 承認期限（日数指定、1〜99日） |
| **期限後動作** | なし / 自動承認 / 自動却下 |

### 6.5 承認方法の詳細

| 承認方法 | ロジック | 使用例 |
|---------|--------|--------|
| **順次** (single) | 1名が承認すれば通過 | 通常の個別承認 |
| **全員** (all) | 全員が承認しなければ通過しない | 合議制の承認 |
| **グループ** (group) | 指定人数以上が承認すれば通過 | 取締役会（3名中2名以上） |
| **通知のみ** (notify) | 承認不要、通知のみ | 情報共有ステップ |

### 6.6 経路マスタの一括CSV管理

#### エクスポート
1. **「一括エクスポート」** ボタンをクリック
2. 全経路マスタ + ステップがCSVでダウンロードされる
3. ワークフローフィルタを設定すると、そのワークフローの経路のみ出力

#### インポート
1. **「一括インポート」** ボタンをクリック
2. CSVファイルを選択
3. プレビューで内容を確認
4. インポートモード選択：
   - **マージ**: 既存の同名経路を更新、新規は追加
   - **置換**: 既存の同名経路を削除して再作成

#### CSVフォーマット

```
経路名,説明,ワークフロー名,経路タイプ,優先度,標準経路,ステップ順,ステップ名,役割タイプ,承認方法,必要人数,必須,期限日数,期限後動作
社長決裁（基本）,基本経路,稟議書,基本,50,はい,1,課長承認,承認者,順次,1,はい,3,
,,,,,,2,部長承認,承認者,順次,1,はい,3,
,,,,,,3,社長決裁,決裁者,順次,1,はい,5,
```

- 経路名がある行 = 新しい経路マスタの開始
- 経路名が空の行 = 直前の経路のステップ継続

### 6.7 経路マスタのコピー

既存の経路マスタをコピーして新しい経路を作成できます。ステップも全てコピーされます。

## 7. ワークフロー管理

> **対象**: 管理者・マネージャーのみ

### 7.1 ワークフロー定義

「ワークフロー」タブでワークフロー定義を管理します。各ワークフローには以下の設定があります：

| 設定 | 説明 |
|------|------|
| **名前** | ワークフロー名（例: 「稟議書（1,000万円以上）」） |
| **説明** | ワークフローの説明 |
| **カテゴリ** | 分類（経費精算、稟議、休暇申請など） |
| **フォームスキーマ** | 入力フォームの定義 |
| **有効/無効** | ワークフローの使用可否 |

### 7.2 詳細設定

#### 採番設定
| 設定 | 説明 |
|------|------|
| **番号フォーマット** | 文書番号の形式（例: `%Y%m-%N%N%N` → 202602-001） |
| **次番号** | 次に採番される番号 |

#### 操作許可
| 設定 | 説明 |
|------|------|
| **取り下げ許可** | 申請者による取り下げを許可 |
| **引き上げ許可** | 上位者による承認引き上げを許可 |
| **再利用許可** | 過去の申請の再利用を許可 |
| **経路変更許可** | 承認途中の経路変更を許可 |

#### 閲覧制限
| 設定 | 説明 |
|------|------|
| **全員** | 全ユーザーが閲覧可能 |
| **経路関係者のみ** | 承認経路に含まれるユーザーのみ |
| **同一部署のみ** | 同じ部署のユーザーのみ |
| **指定ユーザー** | 個別に指定したユーザーのみ |

#### 件名自動入力
| モード | 説明 |
|--------|------|
| **なし** | 手動入力 |
| **基本情報から** | ワークフロー名 + 日付で自動生成 |
| **フィールドから** | フォームの値から自動生成 |
| **テンプレート** | テンプレート文字列から生成 |

### 7.3 ワークフローのコピー

既存のワークフローをコピーして新しいワークフローを作成できます。承認ステップも全てコピーされます。

## 8. 承認ロール管理

> **対象**: 管理者・マネージャーのみ

### 8.1 承認ロールとは

役職ではなく、承認業務上の「役割」を定義するものです。例えば「経理承認者」「人事承認者」など、部署横断的な承認権限を設定できます。

### 8.2 承認ロールの管理

1. 「承認ロール」タブを開く
2. ロールの作成・編集・削除
3. メンバーの追加・削除

### 8.3 メンバー割り当て

各ロールにユーザーを割り当てます：

| 設定 | 説明 |
|------|------|
| **ユーザー** | 割り当てるユーザー |
| **対象組織コード** | このロールが有効な組織範囲（空の場合は全組織） |
| **有効開始日** | ロール割り当ての開始日 |
| **有効終了日** | ロール割り当ての終了日（空の場合は無期限） |

## 9. 代理設定

### 9.1 代理の種類

| 種類 | 説明 | 使用場面 |
|------|------|---------|
| **申請代理** (application) | 他者に代わって申請を提出 | 秘書が上司の代理で申請 |
| **処理代理** (processing) | 他者に代わって承認・処理 | 不在時の代理承認 |

### 9.2 代理設定の作成

1. 代理設定画面を開く
2. 以下を設定：
   - **委任元**: 代理される人
   - **代理者**: 代理する人
   - **代理タイプ**: 申請代理 / 処理代理
   - **対象ロール**: 代理が有効なステップ役割（承認者/決裁者/業務担当者/通知）
   - **有効開始日**: 代理期間の開始
   - **有効終了日**: 代理期間の終了（空の場合は無期限）

### 9.3 代理承認時の記録

代理で承認した場合、承認履歴には以下が記録されます：
- **承認者**: 本来の承認者名
- **代理承認者**: 実際に操作した代理者名

## 10. インポート・エクスポート

> **対象**: 管理者・マネージャーのみ

### 10.1 組織マスタ インポート

#### CSVフォーマット
```csv
code,name,level,parent_code,is_active
CORP,本社,company,,true
SALES,営業本部,division,CORP,true
SALES1,営業1部,department,SALES,true
```

| カラム | 説明 |
|--------|------|
| code | 組織コード（一意） |
| name | 組織名 |
| level | 階層（company / division / department / section） |
| parent_code | 親組織のコード |
| is_active | 有効フラグ |

#### 操作手順
1. 「インポート」タブを開く
2. 「テンプレートダウンロード」でフォーマットを取得
3. CSVファイルを準備
4. 「組織マスタ インポート」でファイルを選択
5. プレビューで確認後、インポート実行

### 10.2 ユーザー インポート

#### CSVフォーマット
```csv
lark_user_id,name,email,role,is_active
f9ebgf54,三宅太一,miyake@example.com,admin,true
```

| カラム | 説明 |
|--------|------|
| lark_user_id | Lark ユーザーID |
| name | 氏名 |
| email | メールアドレス |
| role | 権限（admin / manager / user） |
| is_active | 有効フラグ |

### 10.3 Larkメンバー同期

Lark Contact APIから組織・ユーザー情報を自動同期します。

1. 「インポート」タブの **「Lark メンバー同期」** をクリック
2. 同期結果が表示される

## 12. 承認ステップの仕組み

### 12.1 ステップタイプ（承認者の決定方法）

| タイプ | 説明 | 承認者の決定方法 |
|--------|------|----------------|
| **役職** (position) | 申請者の所属組織の特定役職者 | 申請者の組織 → 上位組織へ探索 |
| **承認ロール** (role) | 特定の承認ロールを持つユーザー | ロール割り当て + 組織コードで検索 |
| **特定ユーザー** (specific_user) | 固定のユーザー | 直接指定 |

### 12.2 役割タイプ（ステップの機能）

| 役割 | 説明 | 条件付承認 |
|------|------|:---------:|
| **承認者** | 通常の承認者 | - |
| **決裁者** | 最終判断を行う承認者 | O |
| **業務担当者** | 業務処理を行う担当者 | - |
| **通知** | 通知を受けるのみ（承認不要） | - |

### 12.3 自動スキップ

以下の条件でステップが自動的にスキップされます：

| スキップ条件 | 説明 |
|-------------|------|
| **同一人物スキップ** | 前のステップと同じ承認者の場合にスキップ |
| **空席スキップ** | 該当する承認者が存在しない場合にスキップ |
| **条件不一致スキップ** | ステップの条件がフォームデータと一致しない場合にスキップ |

## 13. PDF出力

### 13.1 PDF出力方法

1. 申請詳細画面を開く
2. **「PDF出力」** ボタンをクリック
3. PDFが新しいタブで開かれる

### 13.2 PDF内容

| セクション | 内容 |
|-----------|------|
| ヘッダー | 「申請書」タイトル |
| 基本情報 | 文書番号、件名、ワークフロー名、ステータス、提出日 |
| フォーム内容 | 申請時に入力した全フィールドの値 |
| 承認経路 | 各ステップの承認者名とステータス |
| 承認履歴 | 承認・却下・差戻しのタイムライン（コメント含む） |

### 13.3 設定

ワークフローごとにPDF設定が可能：
- **用紙サイズ**: A4縦 / A4横 / B5縦 / B5横
- **余白**: 上下左右の余白（mm）
- **PDF有効/無効**: ワークフローごとにPDF出力の可否を設定

## 14. トラブルシューティング

### よくある問題と対処法

#### 「承認待ちに申請が表示されない」
- **原因**: ログインユーザーが現在のステップの承認者として割り当てられていない
- **対処**:
  - ユーザー役職の設定を確認（「ユーザー役職」テーブル）
  - 承認ロールの割り当てを確認（「承認ロール」タブ）
  - 代理設定が必要な場合は設定を確認

#### 「経路マスタがありません」と表示される
- **原因**: ワークフローに紐づく経路マスタが未作成
- **対処**: 「経路マスタ」タブで対象ワークフローの経路マスタを作成

#### 「ステップが自動スキップされてしまう」
- **原因**: 同一人物スキップ or 空席スキップが有効
- **対処**:
  - 承認者が正しく割り当てられているか確認
  - ステップのスキップ設定を見直す

#### 「CSVインポートでエラーが出る」
- **原因**: CSVフォーマット不一致、必須項目の欠落
- **対処**:
  - テンプレートCSVを再ダウンロードして形式を確認
  - 文字コードがUTF-8（BOM付き）であることを確認
  - 必須項目（コード、名前等）が全行に含まれていることを確認

#### 「Lark同期で0件になる」
- **原因**: Larkアプリの連絡先権限スコープが不足
- **対処**: Lark管理画面でアプリの連絡先範囲を設定
  - 必要なスコープ: `contact:department.organize:readonly`, `contact:user.base:readonly`
